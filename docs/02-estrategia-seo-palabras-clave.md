
**Enlazado interno (implementado):**
- Cada calculadora enlaza a su guía de apoyo en el texto y a 2-3 calculadoras relacionadas en la barra lateral.
- Cada guía enlaza a sus calculadoras («Calculadoras útiles») y a guías hermanas dentro del texto.
- La portada enlaza a todas las calculadoras y a las seis primeras guías; el pie enlaza a todas las calculadoras y páginas institucionales.
- La calculadora de actualización enlaza al generador de carta **con los datos rellenados** (flujo de tarea completo).

**Reglas de URL:** minúsculas, sin fechas ni años en la ruta (para no tener que cambiarlas), barra final siempre (`trailingSlash: 'always'`), sin parámetros indexables (los parámetros de las calculadoras no cambian la canónica).

## 2.3 SEO técnico implementado

| Elemento | Implementación |
|---|---|
| HTML semántico | `header`, `nav`, `main`, `article`, `aside`, `footer`; un solo `h1` por página (comprobado por `qa:dist`) |
| Title y description únicos | Definidos por página; `qa:dist` falla si se repiten |
| Canónicas | Absolutas a partir de `PUBLIC_SITE_URL`, comprobadas en cada página |
| Sitemap | `@astrojs/sitemap` con `lastmod` real (fecha de revisión de cada página); excluye la 404 |
| robots.txt | Generado: bloquea todo en modo revisión; en producción permite e indica el sitemap |
| Control de indexación | `PUBLIC_SITE_INDEXABLE`: `noindex` + `X-Robots-Tag` hasta el lanzamiento |
| Datos estructurados | `BreadcrumbList` en todas las páginas internas, `WebSite` en portada, `Article` en guías (con fechas reales). **No** se usa `FAQPage` (Google retiró ese resultado enriquecido en 2026) ni `SoftwareApplication` (exigiría valoraciones reales) |
| Migas de pan | Visibles y en JSON-LD |
| Imágenes | Sin imágenes pesadas; iconos SVG en línea; imagen OG 1200×630 optimizada |
| Rendimiento | HTML estático, CSS y JS externos cacheables, sin fuentes externas, JS solo en calculadoras (≈5-20 KB). Lighthouse local: 100 en rendimiento (ver `docs/10-qa-resultados.md`) |
| 404 | Página propia con estado 404 y enlaces útiles |
| Redirecciones | No hay URLs antiguas. Si cambias una URL, añade un archivo `public/_redirects` (formato Cloudflare/Netlify): `/ruta-antigua/ /ruta-nueva/ 301` |
| Paginación | No necesaria con el volumen actual |
| Duplicados | Una URL por intención; parámetros de cálculo no indexables (canónica limpia) |
| Accesibilidad | Contraste AA, foco visible, etiquetas y errores asociados, regiones `aria-live`; 0 violaciones graves en axe |

## 2.5 Plantilla para nuevas guías

Copia cualquier archivo de `src/content/guias/` y cambia el frontmatter. El esquema (en `src/content.config.ts`) obliga a incluir título (≤ 70 caracteres), descripción (70-170), H1, resumen, fechas y al menos una fuente oficial. La compilación falla si falta algo.

## 2.6 Cómo completar los volúmenes con Keyword Planner

1. Entra en [Google Ads](https://ads.google.com/) con tu cuenta de Google → Herramientas → Planificación → **Planificador de palabras clave** → «Obtener volumen de búsquedas y previsiones».
2. Pega las palabras clave principales y variantes de la tabla 2.1. Ubicación: España. Idioma: español.
3. Descarga el CSV. Copia en una hoja de cálculo «Promedio de búsquedas mensuales» (rango) y «Puja por la parte superior de la página (intervalo alto)».
4. Reordena las prioridades del plan: sube los grupos con más volumen y pujas altas que puedas cubrir con una herramienta; baja los que tengan volumen muy bajo.
5. Repite cada trimestre y, sobre todo, usa los datos **reales** de Search Console a partir del segundo mes.
